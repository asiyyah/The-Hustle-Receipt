# Paystack Payment Flow

## Overview

The Hustle Receipt uses Paystack's **Initialize Transaction** flow with a hosted checkout page. Users are redirected to Paystack to complete payment, then sent back to the app for verification.

## Architecture

```
Frontend (Tip Form)
  → POST /api/payments/initiate
    → Paystack Initialize Transaction API
    → Creates Tip record (status: pending)
    → Returns authorization_url
  → User redirected to Paystack checkout
  → User completes payment
  → Paystack redirects back to /tip/[slug]/success?reference=xxx
    → POST /api/payments/verify
      → Paystack Verify Transaction API
      → Tip updated to "verified"
    → User sees success page

Paystack also sends webhook (parallel):
  POST /api/webhooks/paystack
    → Verifies transaction independently
    → Updates tip if not already verified (idempotent)
```

## API Endpoints

### POST /api/payments/initiate

Initiates a payment and returns a Paystack checkout URL.

**Request body:**
```json
{
  "creatorSlug": "john-doe",
  "supporterEmail": "supporter@email.com",
  "supporterName": "Jane Smith",
  "amount": 1000,
  "message": "Great work!",
  "paymentMethod": "card"
}
```

**Response:**
```json
{
  "authorizationUrl": "https://checkout.paystack.com/...",
  "reference": "TIP-Ab3k9x-1751400000000"
}
```

**What happens:**
1. Validates required fields (`creatorSlug`, `supporterEmail`, `amount`, `paymentMethod`)
2. Looks up creator in database
3. Generates unique transaction reference via `generateTxRef("TIP")`
4. Calls Paystack Initialize Transaction API (amount sent in kobo × 100)
5. Creates `Tip` record with status `pending`
6. Returns `authorization_url` for frontend redirect

### POST /api/payments/verify

Verifies a completed payment using the transaction reference.

**Request body:**
```json
{
  "reference": "TIP-Ab3k9x-1751400000000"
}
```

**Response (success):**
```json
{
  "message": "Payment verified successfully",
  "tip": { ... }
}
```

**What happens:**
1. Calls Paystack Verify Transaction API
2. Checks `status === "success"`
3. Validates amount (Paystack returns kobo, divided by 100 to match)
4. Validates currency matches
5. Updates tip: `paymentStatus → "verified"`, stores `paystackTransactionId` and `paystackReference`

### POST /api/webhooks/paystack

Handles Paystack webhook events (secondary verification path).

**Headers:** `x-paystack-signature` (currently not validated — add webhook secret to `.env` if needed)

**Handles event:** `charge.success`

**What happens:**
1. Parses webhook payload
2. Verifies transaction via Paystack API
3. Looks up tip by transaction reference
4. Updates tip to verified (idempotent — skips if already verified)

## Database Schema

```prisma
model Tip {
  id                   String   @id @default(cuid())
  amount               Int      // Amount in NGN (kobo / 100 from Paystack)
  currency             String   @default("NGN")
  supporterName        String?
  supporterEmail       String
  message              String?
  transactionReference String   @unique  // Our unique ref, passed to Paystack
  paymentMethod        String            // "card", "bank_transfer", etc.
  paystackReference    String?           // Paystack's reference on verification
  paystackTransactionId Int?             // Paystack's transaction ID
  paymentStatus        String   @default("pending")  // "pending" → "verified"
  creatorId            String
  createdAt            DateTime @default(now())
}
```

## Transaction Reference Format

Generated by `generateTxRef("TIP")` in `src/lib/slug.ts`:
```
TIP-Ab3k9x-1751400000000
│   │        │
│   │        └── Timestamp (ms)
│   └── 6-char random alphanumeric
└── Prefix
```

## Paystack Library (`src/lib/paystack.ts`)

| Function | Purpose |
|----------|---------|
| `initializeTransaction()` | Calls Paystack Initialize API, returns `authorization_url` |
| `verifyTransaction()` | Calls Paystack Verify API, returns transaction details |
| `verifyWebhookSignature()` | Validates `x-paystack-signature` (HMAC-SHA512) |

## Key Notes

- **Amount conversion**: Paystack expects amounts in **kobo** (×100). The app stores amounts in **NGN**. Conversion happens in the API routes.
- **No card handling**: Unlike Flutterwave, Paystack handles all card data on their hosted checkout page. No encryption or card fields needed on our end.
- **Webhook setup**: Configure `https://yourdomain.com/api/webhooks/paystack` in Paystack dashboard under Settings → Webhooks.
- **Test mode**: Use `sk_test_...` keys. Switch to `sk_live_...` for production.
